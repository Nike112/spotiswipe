# Rubric mapping — 10 marks

| Criterion                     | Marks | Evidence in this project                                                                                                                           | What to demonstrate                                                                               |
| ----------------------------- | ----: | -------------------------------------------------------------------------------------------------------------------------------------------------- | ------------------------------------------------------------------------------------------------- |
| Understanding of AWS          |     2 | Amazon Personalize workflow, distinctions between dataset/solution version/campaign, algorithms and limitations                                    | Explain why the service fits music recommendation and what each resource does                     |
| Core functionality/simulation |     3 | Validated import; background training; version snapshots; evaluation; explicit deploy/rollback; ranked recommendations; event feedback and filters | Train a second model, show v1 still serving, deploy v2, roll back, and inspect events/requests    |
| Meaningful enhancement        |     2 | Playlist-level relevance/novelty/coverage objective with duration and artist limits; two measured baselines                                        | Build a short mix, vary discovery and compare genre coverage against the same-constraint baseline |
| UI/UX and working website     |     1 | Real licensed audio, swipes, undo, genre preferences, multiple profiles, player, saved library, responsive controls and offline cache              | Listen, swipe, save a mix, reload and play it                                                     |
| Deployment/GitHub             |     1 | Organized repository, tests/CI, static build and manual Pages workflow                                                                             | Publish after faculty approval and submit actual repository/deployment URLs                       |
| Demonstration/explanation     |     1 | In-app project guide, architecture, demo script, viva answers and verification                                                                     | Explain the end-to-end flow and acknowledge the simulation's boundaries                           |

The implementation supports these criteria; faculty determines the marks. Website publication and form submission must be verified separately. A local campaign Deploy button changes the serving model and must not be confused with publishing the website.
